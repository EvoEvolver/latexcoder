Built for the agent era

Let your coding agent
write in the paper.

Copy one command from the Collaborate menu. Your agent gets a plain-text manual for this project — files, search, compile, review, Git — and edits through a checked protocol that never overwrites a coauthor.

  1. Download the file it wants to change.
  2. Edit with ordinary local tools.
  3. Upload with the original hash. If someone edited meanwhile, the upload is rejected — not merged blindly.

Switch to Propose mode and every agent change arrives as a tracked suggestion you accept or reject.

~/paper
$ claude "Tighten the abstract and fix the
  citation style in our LaTeX Coder paper"

The writing surface

Small things that add up
to hours every week.

01

Hover to see it. Click to go there.

Hover a \ref to see the equation or figure it points to — even from another file. Hover a citation for its title and authors. ⌘-click jumps to the label, the BibTeX entry, or the included file.

02

Review that lives in the source.

Comments and suggestions are LaTeX macros, not rows in a hidden database. Humans, agents, and git diff all see the same review. Resolved threads keep their history.

03

Know who wrote every character.

Blame mode shows authorship right in the editor — person, agent, or Git commit — and links each range to the checkpoint that introduced it.

04

Git without a second source of truth.

The live document is main. Browser edits are checkpointed automatically, so a git pull always sees the latest text, and pushes merge straight into what your coauthors are typing.

  • SyncTeX both ways — source to PDF and back.
  • Chapter builds compile just the chapter you are on.
  • Readable logs that jump to the first fatal error.
  • Citation autocomplete with titles and authors.
  • Project search with regex and previewed replace.
  • History with per-file diffs and one-click restore.
  • Markdown notes beside LaTeX, with live preview.
  • English, 中文, 日本語 interface.
