Not another Overleaf§1–2

1 How this started

We set out to clone Overleaf.

→ fix. Cloning it meant cloning every pitfall.

We wanted our research group to have its own Overleaf, on its own server. Halfway through, it was clear that a faithful clone would also copy everything that gets in a research team’s way. So we stopped copying and started fixing, one pitfall at a time. Table 1 lists what changed.

Table 1. What got in the way, and what we built instead.
What got in the wayWhat LaTeX Coder does
Review that a Git push can wipe outComments and suggestions are LaTeX macros in the source; they survive Git, ZIP exports, and agents.
A Git bridge that flattens historyA real Git repository per paper: clone over SSH, push, merge, restore. Conflicts land on their own branch.
Copy-pasting into a chat windowCoding agents edit the live paper, and can be limited to reviewable suggestions.
Collaborator limits and sign-up wallsView and edit links for guests, with no account and no seat count.
Unpublished work on someone else’s cloudPlain files and Git repositories on your own volume. Leaving is a git clone.
Compile limits on the free tierFull TeX Live and Tectonic on your hardware, with chapter-level builds for long theses.

2 Coding agents as coauthors

Copy one command from the Collaborate menu and hand it to Claude Code, Codex, or any shell agent. The agent receives a plain-text manual for this project — files, search, compilation, blame, review, and Git — and edits through a deliberately simple protocol.

Algorithm 1 Checked edit, as run by an agent

  1. download f;  h ← hash(f)
  2. f′ ← edit(f) with ordinary local tools
  3. upload (f′, h)
  4. if the server’s hash of f ≠ h then
  5. reject — a coauthor edited meanwhile; re-read and retry
  6. else apply f′ in one transaction

Remark. Switch the agent to Propose and every change it makes arrives as a tracked suggestion that you accept or reject, exactly like a coauthor’s.

3 The writing surface

Small things that add up to hours every week. We state them as results.

Proposition 1 (Hover to see it). Hovering a \ref or \eqref shows the equation or figure it points to, even from another file. Hovering a \cite shows the title and authors. ⌘-click jumps to the label, the BibTeX entry, or the included file.

Proposition 2 (Review lives in the source). Comments and suggestions are LaTeX macros, not rows in a hidden database. Humans, agents, and git diff all see the same review, and resolved threads keep their history.

Proposition 3 (Blame). Every character knows who wrote it — a person, an agent, or a Git commit — and links to the checkpoint that introduced it.

Proposition 4 (One source of truth). The live document is main. A git pull always sees the latest text, and a push merges into what your coauthors are typing.
